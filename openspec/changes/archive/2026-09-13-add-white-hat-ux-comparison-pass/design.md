## Context

See `proposal.md` for motivation. This is a content-only comparison pass, structurally identical to the five prior ones recorded in `CHANGELOG.md` (0.1.6-0.1.10): read a book cover-to-cover, cross-check its extracted claims against the existing rule catalog in `src/skills/*/references/*.md`, and add only the subset that is (a) not already covered, even approximately, and (b) checkable from review evidence rather than describing team process, research methodology, or philosophical posture. No skill boundaries, file layout, build pipeline, or shared model (`src/shared/`) changes.

All twelve new rules were pre-scoped to a specific destination file (`usability/references/core.md`, `psychology/references/attention.md`, `trust/references/core.md`, `product/references/core.md`) before this change was created, confirmed against a full read of those four files plus `psychology/references/ethics.md` and `psychology/references/behavioral-economics.md` to rule out duplication.

## Goals / Non-Goals

**Goals:**
- Add exactly the twelve rules listed in `proposal.md`, each traced to a named, independently verifiable source (the book itself for its own case-study-grounded patterns, Gestalt's Law of Similarity for the ad-disguise rule, NN/g's Deceptive Patterns research where the book's pattern maps onto it).
- Keep every new rule ID additive: no existing rule ID, table, or file is restructured, renamed, or removed.
- Cite the book in `README.md`'s Evidence base and in a new `CHANGELOG.md` entry, matching the exact style of the 0.1.6-0.1.10 entries (what was added, what was deliberately scoped out and why).
- Preserve the one-rule-ID-to-exactly-one-destination-file invariant: none of these twelve rules duplicates or fragments an existing rule ID across domains.

**Non-Goals:**
- No new skill, no new shared cross-lens file for "dark patterns" as a taxonomy — each rule lands in whichever single existing skill/file already owns its mechanism, per the user's explicit scope decision.
- No e-commerce/checkout vertical (faceted search standards, checkout-flow architectures, cart UI) — deferred exactly as prior e-commerce-vertical content was in CHANGELOG 0.1.9.
- No strategic/management content (cost-of-fix multiplier, KPI baseline framework, POLA, Agile integration pipeline, service-recovery protocol, backlash dynamics) — process/organizational content, not checkable from review evidence.
- No testing-methodology content (paper prototyping, inherent-value testing, A/B-testing rules, test-report format) — describes how to run research, not what a static review checks.
- No ethical-philosophy/terminology content (rights hierarchy, "people not users" terminology, zero-knowledge/decentralized-architecture stance) — team posture/architecture philosophy, not checkable from typical review evidence.
- No new rule IDs for Friend Spam, Ad Click Harvesting, Ghost Subscriptions, Double Payment Trap, or Forced Unwanted Add-ons — each is either too narrow/single-case (Friend Spam), concerns a third party's site rather than the product under review (Ad Click Harvesting), or folds conceptually into the new generalized cost-disclosure-timing rule (the other three).
- No change to model-invocation defaults: all four touched skills (`usability`, `psychology`, `trust`, `product`) remain model-invocable by default, unchanged from v1.

## Decisions

1. **Distribute rules into existing domain files by mechanism, rather than a new shared file.** Every prior comparison pass added rule IDs directly into the domain file whose existing scope already matched the mechanism (for example eye-tracking form-layout findings went into `usability/references/core.md`'s Forms section). The alternative — a new `src/shared/dark-patterns.md` cross-lens taxonomy — was considered and rejected: it would require every one of the four affected skills' `SKILL.md` procedures to reference a new shared file outside their own `references/` tree, diverging from the established shared/ model (which is reserved for evidence/severity/report-contract, not domain rule content), for no benefit over the simpler per-file placement the project has always used.
2. **One generalized cost-disclosure rule instead of five narrow ones.** The book documents Hidden Costs, Ghost Subscriptions, Double Payment Trap, and Forced Unwanted Add-ons as distinct named patterns, but they share one underlying mechanism: a mandatory cost or fee is withheld until after the user has invested effort or made a decision. Rather than four narrow rule IDs (three of them backed only by a single named case study each), this pass adds one rule in `trust/references/core.md` stated generally enough to cover all four mechanisms, consistent with how this project already generalizes rather than enumerating every book example as its own ID (see the existing `PB03`/`PB08` pattern in `behavioral-economics.md`, which already generalizes several of the book's other patterns — Misdirection/Most-Sensible-Default and Scare-Tactics/fake-urgency — without new rule IDs, confirmed during the comparison and requiring no change here).
3. **Ad Law-of-Similarity rule placed in `psychology/attention.md`, not `trust`.** Its mechanism (Gestalt grouping causing users to misidentify a control's function) is a perceptual/attention mechanism, the same category as the existing `PA09` banner-blindness rule it mirrors, so it belongs beside `PA09` rather than in `trust`, which is scoped to permission/onboarding timing, destructive-action safety, and notification honesty rather than visual perception. It is still routed through `ethics.md`'s four-gate test before being reported as a deception finding, exactly as `PA09`'s sibling rules already are.
4. **Bait-and-Switch and Road Block placed in `usability`, not `trust`.** Both concern the mechanics of a specific control or dialog behaving other than its face value promises (a close button; a blocking modal) — squarely `usability`'s existing Actions section territory (alongside `A01R`-`A08R`), not `trust`'s narrower permission/destructive-action/notification remit.
5. **Trick Questions placed in `product`, not `trust` or `psychology`.** It is a content/copy-logic defect (how a checkbox's label maps to its actual effect), which is `product`'s existing Content-rules territory (alongside `C13`'s confirm-shaming rule), not a permission-timing or persuasive-mechanism concern.

## Risks / Trade-offs

- **[Risk]** The generalized cost-disclosure rule (Decision 2) is broader than the book's own individually named patterns, so a future comparison pass might find a cost-related pattern that doesn't cleanly fit it. **[Mitigation]** The rule's scenarios are written narrowly around "mandatory fee disclosed only at final commitment step" — a genuinely different cost-related failure (for example a *fake* discount, which is a truthfulness/anchoring issue already covered by `PB03`) would not collide with it.
- **[Risk]** Placing the ad Law-of-Similarity rule in `psychology` rather than `trust` could make it less discoverable for a reviewer expecting all "dark pattern"-flavored findings under `trust`. **[Mitigation]** `trust`'s own `SKILL.md` description already explicitly defers persuasive/visual-deception concerns to `psychology` ("Not for ... persuasive-mechanism ethics unrelated to trust/permissions (use `psychology`)"), so this is consistent with the existing boundary, not a new inconsistency.
- **[Risk]** Two of the seven new `usability` rules (breadcrumbs/footer, positive real-time validation) are lower-severity polish items compared to the others (Bait-and-Switch, Road Block) — bundling them in one pass could make the changelog entry read as uneven in weight. **[Mitigation]** Severity is assigned per rule in the reference tables (moderate for these two, higher for the deception-adjacent ones), consistent with how this project already mixes severities within a single comparison-pass changelog entry.

## Migration Plan

Pure additive content change: new rule rows in four existing Markdown reference tables, new spec requirements, a version bump, and a rebuild. No data migration, no runtime behavior to roll out gradually. Rollback, if ever needed, is reverting the commit — no persisted state depends on these rule IDs.
