## Context

See `proposal.md` — Why. This is this project's twentieth-plus named-source comparison pass (after Writing Is Designing, eye-tracking research, Digital Minimalism, a UX-team-of-one practice book, White Hat UX, Understanding Context, The Elements of User Experience, Laws of UX, The UX Book, Smashing UX Design, User Experience Design, Seductive Interaction Design, Design for a Better World, and User Story Mapping — see `CHANGELOG.md` 0.1.6-0.1.19). The source is Sean Adams's *How Design Makes Us Think and Feel and Do Things*, whose extracted 28-item knowledge map was compared item-by-item against every existing rule in `src/skills/*/references/*.md` before this proposal was drafted.

## Goals / Non-Goals

**Goals:**
- Add the nine specific, checkable rules the book contributes that no existing rule already covers: design-system visual-variant limiting, sensitive-domain anxiety-reducing labeling, truthful earned-reward guilt-bridging framing, humor-as-buffer for non-error administrative bad news, editorial line-length/type-scale proportions, objective visual tone for sensitive domains, rejection of age-patronizing visual tropes, non-interfering platform branding over user content, and real-world environmental legibility.
- Enrich two existing rule clusters' citations (`product/references/core.md`'s `C20`/`C22`/`C25`/`C26` data-visualization cluster, and `C23`'s polish-vs-trust rule) with named sources this book surfaces, without changing either cluster's behavior or adding a new rule ID.
- Keep every addition mapped to the four existing skills touched (`usability`, `psychology`, `product`, `accessibility`) — no new skill, no new top-level lens, no new reference file.

**Non-Goals:**
- Importing the book's industrial/hardware-design content — biomorphic ergonomics of physical buttons and controls (Eliot Noyes's IBM Selectric, concave key indentation). This is physical-hardware design, not software interaction mechanics, consistent with the book's own "Possible Omissions" self-audit distinguishing its graphic/industrial-design domain from software UX; touch-target ergonomics for actual software controls are already covered by `accessibility`'s `T01`-`T05`.
- Importing the book's brand-identity-system content — a dynamic library of 100 nostalgia-themed logo variants for approachable trust, and heroic low-angle campaign imagery for collective mobilization. Brand/marketing voice is explicitly out of this project's scope per `product/references/voice-tone.md`'s `VT05` guardrail, and prior passes have consistently excluded brand-identity-system content.
- Importing the book's vertical-specific content — pharmacy/OTC packaging combined with smart-kiosk and home-calendar syncing (a healthcare-IoT service-design vertical), and curated-gallery/low-pressure retail layout (an e-commerce vertical). Deferred consistent with this project's established treatment of e-commerce-vertical and other single-industry vertical content in prior passes.
- Adding "pure primary colors are processed by the brain without complex decoding" and "golden-ratio horizontal aspect ratios align with evolutionary scanning biology" as rules. Both are asserted in the source with no independently verifiable research citation behind them — the same evidentiary gap that led the 0.1.6 pass to debunk the unsourced "Miller's Law caps navigation at 7" claim and the 0.1.14 pass to reject this same book's own "Rule of Odds" claim rather than encode either as a rule. Per this project's standing evidentiary bar, both stay excluded.
- Re-deriving rules already covered under different names: visceral/glossy-veneer-over-broken-function (`psychology`'s `PE01`/`PE06`/`PE07`), onboarding/unboxing friction (`trust`'s `O01`-`O03`, `product`'s `P03`/`P06`), physical/interface constraints preventing errors (`usability`'s `E01`), open-ended narrative brand storytelling (out of scope per `VT05`), imperative call-to-action verbs (`usability`'s `A02R`, `accessibility`'s `X14`), wayfinding/real-time status in multi-step flows (`usability`'s `S04`/`R02R`/`R03R`/`N16R`/`CR01`), and fabricated scarcity/countdown urgency (`psychology`'s `PB08`, already Blocker-severity). All are confirmed already covered and left untouched.
- Adding a new rule for Norman's visceral/behavioral/reflective three-level response model. This model is already the implicit organizing structure behind this project's skill split (`psychology` for visceral/emotional mechanisms, `usability` for behavioral/interaction mechanics, `trust`/brand-adjacent content for reflective/identity concerns) rather than a specific checkable rule with its own pass/fail scenario; encoding it as a rule would restate existing skill boundaries rather than add new checkable content.
- A new reference file for any of the nine additions. Each lands in an existing file whose established scope already covers its topic (Actions in `usability/core.md`, emotional UX in `psychology/emotion.md`, behavioral economics in `psychology/behavioral-economics.md`, voice/tone in `product/voice-tone.md`, web typography in `product/web.md`, content in `product/core.md`, and mobile-specific accessibility in `accessibility/mobile.md`) — none contributes enough independent conceptual weight on its own to justify a new file, per this project's established file-growth precedent.

## Decisions

**`A17R` lands in `usability/references/core.md`'s Actions table, not a new "design system" section.** Variant-proliferation across button styles/fonts/colors is a control-level consistency concern of the same shape as the file's existing `A01R`-`A16R` rules (each governs how a control or set of controls should behave/appear), just scoped to the product level rather than a single screen. It is explicitly distinguished in its own requirement text from `A01R` (single-screen hierarchy) and `A13R` (single-control label matching), so it does not duplicate either.

**`PE08` (sensitive-domain labeling) lands in `psychology/references/emotion.md`, not `product/references/core.md`'s `C15`.** `C15` governs *dignity* in describing disability/human traits — objective phrasing over tragic/heroic framing. `PE08` governs *anxiety-driven hesitation or mis-selection* when a user must choose among sensitive category labels — a different psychological mechanism (self-image threat causing avoidance or error) than dignity-in-description. Both can coexist on the same form without either being redundant: a label could be dignified in Chomsky-neutral terms yet still clinical enough to cause hesitation, or vice versa.

**`PB14` (earned-reward framing) lands in `psychology/references/behavioral-economics.md`, continuing the `PB`-series, not `motivation.md`.** Although it touches motivation, its core mechanism — reframing a purchase decision to resolve pre-existing guilt — is a choice-architecture/framing effect in the same family as `PB03` (price anchoring) and `PB04` (loss-framed messaging), both already in `behavioral-economics.md`. Like `PB01`-`PB05` and `PB09`-`PB12`, it is genuinely context-dependent and must still pass the four-gate test in `ethics.md`; it is explicitly not grouped with `PB06`-`PB08`'s fabrication-based guardrails, since a truthful earned-reward frame is legitimate, distinguishing it in the same way `PB13` is distinguished from `PB06`.

**`VT06` is scoped narrowly to non-error administrative messaging, and is written to explicitly not override `E02`/`E03`.** The book's debt-collection-letter example is about a human/administrative relationship (a service provider being lenient about an overdue account), not a system telling a user how to fix a broken interaction. Without an explicit boundary, `VT06` could be misread as license to add cute language to error copy that `E03` already forbids — the requirement text and its spec scenarios name this boundary directly, including a scenario that explicitly defers back to `E02`/`E03` for genuine system errors.

**`C27` (line length) lands in `product/references/web.md`, continuing its `C07`-`C12` series, not a new file.** It is the same kind of scanning/typography concern `web.md` already exists to hold, evidenced independently of this book by established readability research (NN/g line-length guidance), and the file's own scope note ("apply... in addition to `core.md`'s content rules... not... short native UI copy") already bounds it correctly without modification.

**`C28`, `C29`, and `C30` are three separate rule IDs in `product/references/core.md`'s Content table, not one combined "visual respect" rule.** Each is an independently checkable failure mode with a different trigger condition and a different fix: `C28` triggers on subject-matter gravity (medical/legal/grave content) and fixes via visual tone restraint; `C29` triggers on target-audience age (children/teens/older adults) and fixes via removing patronizing tropes; `C30` triggers on content ownership (user-generated/curated content) and fixes via minimizing platform branding. A screen could independently pass or fail any one of the three (for example, dignified age-appropriate design on a grief-support app could still fail `C28` if its stock photography is cheerful and mismatched), so collapsing them into one rule would lose independent testability — consistent with this project's one-rule-ID-to-one-mechanism convention already established for `N20R`/`N21R` and `C19`/`C20`.

**`X16` lands in `accessibility/references/mobile.md`, not `core.md`.** Real-world adverse-condition legibility (outdoor glare, low-end displays, low light) is a mobile-context concern in the same way `X04`/`X05` (text scaling) already are — both require knowing the actual device/usage context rather than being assessable as a universal, platform-agnostic WCAG criterion the way `core.md`'s `X01`-`X15` are. This mirrors the established precedent that `X04`/`X05` (not `core.md`'s sequential `X`-numbering) live in `mobile.md` while continuing the same shared `X`-prefix sequence; `X16` continues that sequence from `core.md`'s current highest (`X15`).

**Citation-only enrichments to `C20`/`C22`/`C25`/`C26` and `C23` are not modeled as spec deltas.** Per `openspec/config.yaml`'s specs rule and this project's own proposal-writing convention ("Modified Capabilities... Only include if spec-level behavior changes"), adding a Sources-column citation changes attribution, not the rule's `SHALL`-equivalent behavior or any scenario — the existing `ux-crux/product` requirements already describe the behavior unchanged. This mirrors the 0.1.15 pass's citation-only enrichment of `C05`/`L07`.

## Risks / Trade-offs

- **Risk:** `VT06`'s permission for "light, self-aware tone" on bad-news administrative copy could be misapplied to genuine system errors, undermining `E02`/`E03`'s existing clarity-first requirement. → **Mitigation:** the requirement text and its spec scenarios explicitly scope `VT06` to non-error, human/administrative messaging and include a scenario that names `E02`/`E03` as controlling for genuine system errors, plus a hard exception for security/safety-critical notifications.
- **Risk:** `PE08`'s "neutral or familiar alternative" standard for sensitive-domain labels is judgment-based and could be over-applied to remove precise terminology a specialist audience actually needs. → **Mitigation:** the requirement's clinical-precision-required scenario explicitly exempts cases where a neutral alternative would introduce misdiagnosis, legal, or informed-consent risk, mirroring the exception structure already used for `C01`'s verified-expert-audience carve-out.
- **Risk:** `PB14`'s earned-reward framing sits close to `PB04`'s loss-framed-messaging guardrail and could be read as license for guilt-based marketing generally. → **Mitigation:** the requirement is explicit that it applies only when effort is genuine and truthfully represented, requires passing the standing four-gate test in `ethics.md`, and its first spec scenario flags fabricated or exaggerated effort as a defect, not a gray area.
- **Risk:** `X16` (real-world legibility) is rarely assessable from a static screenshot alone, mirroring `X04`/`X05`'s existing assessability limits. → **Mitigation:** consistent with this project's evidence model, the requirement's spec explicitly directs a `NOT ASSESSABLE` report naming outdoor/low-end-device testing as the validation method, rather than guessing pass or fail from a static image.
- **Risk:** `C28`/`C29`/`C30` all key off subjective judgments (what counts as "grave," "patronizing," or "competing" branding) that could be inconsistently applied. → **Mitigation:** each requirement's scenarios anchor the finding to concrete, observable triggers (a stated subject-matter category, a stated target-age audience, a stated content-ownership type) rather than a general aesthetic judgment, and each includes an explicit non-applicability scenario for when the trigger condition is absent.

## Migration Plan

Standard content-only release: implement the `src/skills/**`-adjacent changes, then run `npm run build && npm run sync-version && npm run validate` (this project's standing release gate) before considering the change complete. No runtime migration — this is static Markdown content shipped as Agent Skills; there is no data model or running service to migrate. Rollback, if ever needed, is a plain revert of the commit(s) plus a rebuild.
