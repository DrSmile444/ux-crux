## Why

A comparison pass against Don Norman, *Design for a Better World* (MIT Press, 2023) surfaced eight genuine, specific gaps in the existing rule catalog that no current rule already covers: a delayed-feedback-loop mental-model failure (the thermostat problem), a single-aggregate-number dashboard fallacy distinct from this project's existing audience-complexity and chart-type rules, a narrative-grounding gap for data-dense screens about a human subject, a crisis/high-stress interaction design gap this project's confirmation-dialog and error rules do not address, an "invisible prevention" trust gap for silent background protective systems, a semi-automation complacency-trap gap increasingly relevant to AI co-pilot features, a societal-affordance/signifier gap distinct from the existing four-affordance-type vocabulary, and a "legacy assumption" review technique gap alongside the review skill's existing named techniques (Five-Second Test, Black Hat Session, Role-Play UI Audit). As with all sixteen prior comparison passes (see `CHANGELOG.md` 0.1.6-0.1.17), this is not a wholesale import of the book's full extracted content: its physical-product circular-economy/obsolescence material, its ecosystem-and-decades-scale Humanity-Centered Design thesis, its Agile/Incremental-Modular-Design team-process content, and its organizational-metrics (Goodhart's Law) content describe hardware lifecycles, civilizational-scale design strategy, and team process — not a reviewable software interface pattern — so they have no home in any existing skill.

## What Changes

- `usability`: add a new System status rule to `core.md` — when a user action's effect is delayed rather than immediate, the interface exposes rate/delay explicitly, preventing the extreme-value/oscillation failure mode of a hidden long-delay feedback loop (Norman's air-conditioner/thermostat case). Distinct from existing `S01`/`S04`, which require feedback and progress indication in general, not correction of a delayed-effect mental model specifically.
- `usability`: add a new crisis/high-stress interaction rule to `core.md` — an emergency or acutely time-pressured flow is designed for fast, visceral processing (one prominent single-action control, no multi-step reasoning or dense text), reserving reflective flows for calm states.
- `usability`: extend the affordances vocabulary in `affordances.md` with a new AF rule for societal (convention-based) affordances — a permission/prohibition signifier that relies on unwritten social or procedural convention, distinct from the file's existing four physical/cognitive/sensory/functional affordance types.
- `product`: add a new Content rule to `core.md` — a dashboard, health score, or composite metric does not collapse multiple, especially trade-off, dimensions into one blended number without drill-down access to constituent categories (the GDP/Doughnut Model critique). Distinct from existing `C20` (audience-appropriate complexity) and `C22` (chart-type fit): this is about aggregation hiding sub-category failures, not display complexity or chart type.
- `product`: add a new Content rule to `core.md` — a data-dense screen about a human subject or record (a patient, a user, a transaction) keeps a visible human/narrative context anchor alongside clinical/numeric fields, rather than presenting isolated numbers (Norman's "Medical Cart Syndrome").
- `product`: add a new rule to `core.md` — a semi-autonomous feature (an AI co-pilot, an autopilot-style automation) that hands a rare failure back to a passively monitoring human with no lead time is a design defect; the feature needs either full automation or genuine active-engagement design with explicit decision checkpoints.
- `trust`: add a new rule to `core.md`, parallel to the existing `PR01` post-interaction-reassurance rule — a background protective/maintenance system that works silently (a security scan, an auto-backup, threat blocking) surfaces periodic, non-intrusive positive activity summaries, since users read unexplained silence as proof the protection was unnecessary and disable it (Norman's invisibility-of-prevention/safety-success-backlash case).
- `review`: add a new named technique to `review-model.md`, alongside the existing Five-Second Test, Black Hat Session, and Role-Play UI Audit (all referenced from `V06`) — a "Legacy Assumption Audit": when a UI requirement's only stated justification is "that's how it's always been done," apply an iterative "why" probe to test whether it is a genuine need or an obsolete administrative remnant.
- Citation-only enrichments (no new rule IDs, no behavior change): cite Herbert Simon's satisficing/bounded-rationality research and name the decoy effect explicitly in `psychology/references/behavioral-economics.md`'s `PB03` and `psychology/references/cognitive.md`'s `PC01`/`PC08`; cite Eric von Hippel's Lead User theory and the IKEAhackers.net case as reinforcing evidence for `usability/references/affordances.md`'s `AF02`; cite Norman's "human error is design error" framing as direct named-source backing for `usability/references/core.md`'s `E01`/`E03`; cite the tight/loosely-coupled-systems framing (Toyota JIT vs. Internet routing) for `usability/references/core.md`'s `S10`.

Scoped out (physical-product, civilizational-scale, and team-process content, consistent with every prior comparison pass): Obsolescence modes, Circular Design, and Product-as-a-Service (Part III) describe physical hardware/manufacturing lifecycles and business models, not a reviewable software interface pattern — the one adjacent concern (hardware-tier/connectivity equity) is already covered by `accessibility`'s `X15`. The Five Principles of Humanity-Centered Design (Part IV's core thesis — ecosystem focus, decades-scale impact, designing with/by communities) describes strategic/organizational-scale intent, not something checkable from a static UI/flow evidence review. Incremental Modular Design, Agile/MVP/sprint methodology, and the "Designer as Orchestral Conductor" team-facilitation material (Ch. 25-28) describe how a team runs its own process, not what a static-evidence review checks, matching every prior pass's exclusion of design-sprint/Double-Diamond/Agile content. Goodhart's Law / the proxy-measurement trap (Ch. 8) describes internal team/organizational metric design; the one adjacent case (a gamified metric rewarding the wrong proxy) is already covered by `psychology`'s `PG02`. Searchers vs. Planners / Convivial Tools and tightly-vs-loosely-coupled system architecture are folded into the `AF02` and `S10` citation enrichments above rather than added as standalone new rules, since both territories are already covered by those existing rules.
