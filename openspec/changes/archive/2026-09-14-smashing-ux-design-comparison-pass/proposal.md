## Why

Jesmond Allen & James Chudley's *Smashing UX Design: Foundations for Designing Online User Experiences* (Wiley, Smashing Magazine book series) is a broad UX-process-and-components reference whose extracted knowledge map (33 chapters, 24 atomic items) was compared item-by-item against this project's full existing rule catalog before this proposal was drafted. The comparison surfaced genuine gaps of two shapes: several specific, checkable rules with no existing home (a LATCH-based content-organization check, mutually-exclusive top-level navigation categories, a ban on catch-all navigation buckets, content-vs-ornamental photography, a data-table/dashboard audience-fit check, a faceted-search dead-end guard, and a mobile device-capability input check), and one structural/methodological gap inside `review` itself: the book's Expert Review chapter describes a two-pass evaluation discipline — a persona-driven Cognitive Walkthrough of the primary task(s) followed by a Heuristic Evaluation sweep — that `review/references/review-model.md` does not currently name as an explicit sequence, even though its lens-selection procedure and `V01`-`V06` validation methodology already assume something close to it. Unlike this project's usual treatment of "how a UX team runs its own process" content, this particular item describes how an *expert review* (the exact activity `review` performs) should itself be structured, so it earns a place in `review-model.md` rather than being scoped out as process content, per explicit owner sign-off.

Following this project's established comparison-pass pattern (see `CHANGELOG.md` 0.1.6-0.1.14), this change adds only the specific, checkable, named-source content that is genuinely new — not a wholesale import of the book's full 24-item extraction. The book's process/methodology chapters (the Virtuous Circle of iterative UCD, Agile Sprint-Zero modeling, developers observing usability-test sessions, analytics-as-"what"-vs-qualitative-research-as-"why", search-log mining as an IA-research technique, wireframe data-consistency as a testing-validity concern, and severity-rated-annotated-screenshot report formatting) describe how a UX team runs its own research/design process or formats its own deliverables, not what a static-evidence review checks, and are explicitly left out, consistent with every prior comparison pass's treatment of process content. The book's e-commerce-specific cart/checkout vertical (cart-as-shortlist, non-expiring cart persistence) is deferred, consistent with the 0.1.9 and 0.1.11 passes' identical treatment of e-commerce-vertical content. The book's Rule of Odds (3-or-5-items-per-row product grids) is deliberately excluded as an uncited visual-composition folk claim with no independent, verifiable research source behind it — the same evidentiary bar that led the 0.1.6 pass to debunk the unsourced "Miller's Law caps navigation at 7" folk rule, per explicit owner decision.

## What Changes

- `product`: add one new rule to `references/information-architecture.md` — `IA09` (Richard Saul Wurman's L.A.T.C.H. framework: Location/Alphabet/Time/Category/Hierarchy as the finite set of sort/filter/organization modes a catalog, list, or data table should offer, matched to what the content and task actually need), explicitly distinguished from `IA06`'s structural-topology scope (Tree/Matrix/Organic/Sequential govern how the IA is *structured*; `IA09` governs how an already-structured list is *sorted and filtered* for the user).
- `product`: add two new rules to `references/core.md`'s Content table — `C19` (a content photo that informs a user's decision — scale, quality, craftsmanship, a real concern being addressed — is distinguished from decorative/ornamental stock photography that conveys no product information and erodes trust) and `C20` (a data table, chart, or dashboard is prioritized and filtered for the actual target audience's expertise level, not the data owner's — the "expert knowledge trap" — stripping non-essential columns and jargon rather than displaying every parameter a domain expert would want).
- `usability`: add two new rules to `references/core.md`'s Navigation table — `N20R` (top-level navigation categories are mutually exclusive: a user should never plausibly wonder "could this be under A or B?", sharpening `N01R`'s "mutually meaningful" requirement with an explicit non-overlap test) and `N21R` (navigation never uses a catch-all label — "Miscellaneous", "Resources", "More Info", "Other" — as a dumping ground for content that does not fit the existing structure; the structure is expanded instead).
- `usability`: add one new rule to `references/core.md`'s Search, discovery & comparison table — `D08` (a faceted-filter interface dynamically hides or disables filter options that would produce zero results *before* the user selects them, and provides a single-action control to clear all applied filters at once), sharpening `D04` (no-results messaging) and `D05` (visibility of current filter state) with the specific dead-end-prevention mechanism neither currently requires.
- `usability`: add a new "Forms (platform contracts)" section to `references/mobile.md` with `F24` (a mobile form field that maps to a device capability — camera-based document/card scanning, geolocation-based address autofill, or an OS-level payment sheet such as Apple Pay/Google Pay — uses that capability instead of requiring full manual entry, when the platform provides it and privacy permits), explicitly distinguished from `F04` (keyboard/autocomplete configuration for manually-typed input, not replacing manual entry) and `F10` (password-manager/non-memory authentication, not general form input).
- `review`: add `V07` to `references/review-model.md`'s Validation methodology — a two-phase expert-review structure: a Cognitive Walkthrough of the primary task(s) from a stated or inferable target persona's perspective (step-by-step clarity and system-feedback evaluation) precedes or runs alongside the Heuristic Evaluation sweep the lens-selection procedure and domain skills already perform; when no persona or primary task can be inferred from the evidence, the walkthrough pass is reported `NOT ASSESSABLE` rather than skipped or invented.
- `product`/`usability`: enrich existing rule citations — `product/references/core.md`'s `C05` (inclusive language, localization implications) and `usability/references/mobile.md`'s `L07` (text-expansion/locale formatting) gain a citation to Giles Colborne's hierarchy of localization predictability (Task > Infrastructure/Legal/Market > Translation/Culture, via this book) as the named rationale for why translation/culture is the least predictable, most review-worthy layer — no new rule ID, no behavior change.
- `README.md`: add Jesmond Allen & James Chudley's book to the "Evidence base" list of comparison-pass sources.
- `CHANGELOG.md`: add an entry in the same style as prior comparison-pass entries (0.1.6-0.1.14), naming what was added, what was left out and why (process content, e-commerce vertical, the uncited Rule of Odds), and what was confirmed already-covered (workarounds/cheatsheets as failure signals, forced-registration-in-checkout avoidance, in-context help over isolated FAQ, form-as-conversation minimalism, no app-install walls/touch targets).
- `package.json` version bump (patch) plus `scripts/sync-version.mjs` and `scripts/build.mjs`/`scripts/validate.mjs` runs, per this project's standing release gate.

No new skill is introduced. Everything maps to the three existing capabilities below.
