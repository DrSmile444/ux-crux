## Why

Rex Hartson & Pardha Pyla's *The UX Book: Agile UX Design for a Quality User Experience* (2nd ed., Morgan Kaufmann/Elsevier) is a foundational UX-process and interaction-theory text whose knowledge map was compared item-by-item against this project's full existing rule catalog (~190+ rules across `usability`, `psychology`, `accessibility`, `product`, `trust`). The comparison surfaced genuine gaps of two shapes: several specific, checkable rules with no existing home (an effort-threshold discoverability check, exact button-label-to-destination-header matching, an explicit disabled-control explanation requirement, a guard against automation that seizes user focus, generalized feedback-placement, decorative-visual-clutter avoidance, destructive-control spacing, and chunked-number-formatting), and two structural gaps: Hartson's Four Kinds of Affordances (Cognitive/Physical/Sensory/Functional) has no diagnostic framework anywhere in the catalog even though individual symptoms of affordance failure are already flagged piecemeal, and the Interaction Cycle / Gulf of Execution-Evaluation model has no root-cause classification home in `review`. Following this project's established comparison-pass pattern (see `CHANGELOG.md` 0.1.6-0.1.13), this change adds only the specific, checkable, named-source content that is genuinely new — not a wholesale import of the book's full extracted 28-item set. The book's process/methodology chapters (contextual inquiry, requirements extraction, personas, HCI paradigms, Agile/Sprint-Zero integration, RITE, the Ripple Model) describe how a UX team researches and plans work, not what a static-evidence review checks, and are explicitly left out, consistent with every prior comparison pass's treatment of process content.

## What Changes

- `usability`: add five new rules to `references/core.md` — a new Navigation rule `N19R` (a capability that exists but requires effort beyond a reasonable discovery/interaction threshold to reach is treated as absent, per Larry Marine's Effort Threshold Rule); a new Actions rule `A13R` (a button/link's label text matches, word-for-word, the heading of the screen it navigates to — distinct from `N07R`'s broader synonym-consistency scope and `A09R`'s effect-truthfulness scope); a new Actions rule `A14R` (a disabled/grayed-out control explains why it is unavailable and what would enable it when the user directly interacts with it, sharpening `A08R`'s visual-distinguishability-only requirement); a new Interaction-efficiency rule `IE14` (background/automated processes do not seize input focus or interrupt active user work without consent); and a new System-status rule `S11` (any status/confirmation/error feedback appears within the user's actual focus of attention, generalizing `F07`'s form-specific placement rule to all feedback types).
- `usability`: add two small rules to existing `references/core.md` sections — `A16R` (destructive/high-consequence controls keep generous physical spacing from adjacent safe controls, not just adequate individual target size — a Fitts's-Law-style movement-time concern distinct from `accessibility`'s `T01`/`T02` minimum-size contracts) and `F23` (long numeric identifiers a user must read, compare, or transcribe are displayed in visually chunked groups, not as unbroken digit strings).
- `usability`: add one rule to `references/visual-hierarchy.md` — `VH03` ("flash and trash": purely decorative motion/graphics minimized or removed when they measurably compete with legibility or task-critical attention).
- `usability`: add a new reference file `references/affordances.md` establishing Hartson's Four Kinds of Affordances (Cognitive/Physical/Sensory/Functional) as a diagnostic framework for classifying *why* a flagged interaction defect occurred, cross-referencing rather than duplicating existing symptom-level rules (`A08R`, `A09R`, `A12R`, `accessibility` `X02`/`X03`, `T01`/`T02`) — `AF01` (apply the four-type framework when diagnosing a control-level finding) and `AF02` (a user-created affordance artifact visible in the evidence — a taped label, sticky note, or custom cheat-sheet compensating for the interface — is treated as a strong, evidence-model-`VERIFIED`-leaning signal that a built-in affordance is missing, not merely a curiosity). Wire the new file into `usability/SKILL.md`'s procedure and References section, following the exact pattern already used for `mobile.md` and `visual-hierarchy.md`.
- `review`: add a new "Interaction Cycle & Gulfs" section to `references/review-model.md` — `IC01` (classify a usability breakdown's root cause by Interaction Cycle stage — Planning, Translation, Physical Action, Outcome, or Assessment — rather than reporting a generic complaint, noting Hartson & Pyla's finding that the large majority of real-world breakdowns occur at the Translation stage, so a Translation-stage cause should be considered before assuming a deeper Outcome-stage/backend defect).
- `psychology`: add one new meta-rule to `references/ethics.md` — `PX05` (Slanty Design: deliberate friction on a specific action is ethically legitimate when its purpose is protecting a shared resource, another user, or a legitimate collective/enterprise policy from the acting user — distinct from `trust`'s `E08`, which covers friction as a trust *signal* to the acting user on their own high-stakes action, and distinct from a dark pattern, which extracts a business advantage from the acting user at their own expense).
- `README.md`: add Hartson & Pyla's book to the "Evidence base" list of comparison-pass sources.
- `CHANGELOG.md`: add an entry in the same style as prior comparison-pass entries (0.1.6-0.1.13), naming what was added, what was left out and why, and what was confirmed already-covered (Recognition over Recall, Precise Wording, mode/quasimode handling, basic Fitts target sizing, ego-free error messages).
- `package.json` version bump (patch) plus `scripts/sync-version.mjs` and `scripts/build.mjs`/`scripts/validate.mjs` runs, per this project's standing release gate.

No new skill is introduced. Everything maps to the three existing capabilities below.
