# Information architecture

Platform-agnostic. Covers rules IA01-IA05 from the source catalog. See `../shared/evidence-model.md` and `severity-model.md` for how to report findings from these rules.

IA structure is evaluated across three materials (Dan Klyn's IA framework): **labels/ontology** (what a term means — what we mean when we say what we say), **relationships/taxonomy** (how labeled concepts are categorized and connected to each other), and **rules/choreography** (the conditional logic governing how that structure is placed into the interaction flow itself). A finding under any rule below is a finding about one of these three materials, not an undifferentiated "navigation" complaint — naming which material is off (a label is wrong, a category structure is wrong, or the flow logic around the structure is wrong) sharpens the finding and its fix.

| ID | Rule | Evidence | Default severity | Sources |
|---|---|---|---|---|
| IA01 | Navigation, labeling, and categorization sit at the intersection of user mental models, content structure/volume, and business or technical context — not on internal organizational or system structure alone. A user's mental model starts from an unchosen real-world situation and a discovered need, not always from a pre-formed, explicit goal; an entry point that offers only backend-style task names, with no situational bridge for a user who has not yet identified which task applies to their circumstance, fails this same mental-model check. | Strong | Major | Rosenfeld, Morville & Arango, *Information Architecture for the Web and Beyond*; Andrew Hinton, *Understanding Context* (Situation-Need-Task model) |
| IA02 | When an IA structure's findability has not been validated with users, recommend tree testing over relying on visual-comp review alone. | Strong | Moderate | Donna Spencer, tree testing methodology |
| IA03 | When a catalog, repository, or collection forces every item into a single, mutually exclusive category path, and users plausibly need to find items by more than one independent attribute (for example price, format, and date, rather than category alone), faceted (multi-attribute) classification is recommended instead of a single rigid hierarchy. | Strong | Major | S.R. Ranganathan, faceted classification theory |
| IA04 | User-facing navigation, labeling, or sign-in structure does not expose an internal organizational, departmental, or system division (for example separate sign-in flows or menu sections mirroring internal business units) as if it were a meaningful user-facing distinction. This is distinct from IA01's general mental-model-mismatch check: IA04 flags the specific case where internal corporate language or structure leaks directly into a user-facing boundary, not merely an unclear label. | Strong | Major | Abby Covert, corporate-language/term-disambiguation practice |
| IA05 | A UI metaphor's container/item relationship matches the real-world referent it invokes (for example, do not nest a "roll" of items inside an "album" when the physical referent is the reverse — a roll produces the album). A single, unified label does not silently merge multiple underlying objects or data sources that carry different visibility or permission scopes without visual differentiation, when doing so could cause a viewer to misjudge who else can see an item grouped under that label. | Strong | Major | Andrew Hinton, *Understanding Context* (metaphor fidelity; reified-label misalignment) |

**Applicability note:** IA01 requires visibility into the business/technical context behind a navigation or categorization choice (content volume, existing structure, technical constraints). If that context is missing from the evidence, report `NOT ASSESSABLE` rather than assuming the structure is right or wrong. The situational-entry-point scenario within IA01 requires the same context: if the evidence doesn't show what real-world circumstances bring users to the product, report `NOT ASSESSABLE` rather than assuming a situational bridge is missing.

**Applicability note:** IA03 does not apply merely because a rigid hierarchy exists — it applies only when the evidence supports that users plausibly need an independent, alternative attribute path to the same items. A small catalog with one clear, sufficient organizing dimension does not need faceted classification added for its own sake.

**Applicability note:** IA05's reified-label scenario requires evidence that different viewers (or the same viewer across contexts) would actually see different underlying items under the shared label. If the evidence shows only one viewer's perspective with no indication of a permission or visibility split, report `NOT ASSESSABLE` rather than assuming a misalignment.
