# Changelog

All notable changes to ux-crux are documented here. Versioning follows SemVer; the whole plugin is versioned as one unit (see `src/skills/review/references/review-model.md`'s sibling design note in `design.md` for why).

## 0.1.10 — voice/tone axis and ten targeted rule additions from a UX-writing comparison pass

Added a set of specific, named-source rule additions found while comparing this project's existing catalog against Michael J. Metts & Andy Welfle, *Writing Is Designing: Words and the User Experience* (Rosenfeld Media, 2nd ed., 2020). Not a wholesale import of that book's full extracted item set — its own process/strategy/team-practice frameworks (a Product Strategy Statement "Mad Libs," an Exposure Hours team-contact metric, neutral-interview and highlighting/underlining testing as team *research methods* rather than review checklist items, plain-text-editor prototyping, a call-center-cost internal-advocacy technique, a "This, but Not That" voice-guideline-authoring framework, a tone-profile-audit workflow, Office Hours/meeting-integration tactics, facilitation protocols, and Shopify-Polaris-style design-system collaboration architecture) describe how a UX-writing practice/team operates, not what a static-evidence review should check, so they have no home in any existing skill; an AI-suggested-reply sentiment-safety pattern (messaging-app "smart reply" chips) was also scoped out as too narrow/platform-specific to generalize into any of the six skills. Everything already covered (the Usable/Useful/Responsible triad against the existing four-gate ethical test, Positive Error Reframing plus Avoid-Explain-Resolve against `usability`'s E01-E04, color/icon independence against `accessibility`'s X02) was left untouched; a proposed metaphor-consistency audit was judged too broad/unfalsifiable without a narrower named source and deliberately skipped.

- `product`: new reference file `references/voice-tone.md` establishes Voice & Tone as a reviewable axis (`VT01`-`VT05`) — a Clear-before-Concise-before-Human priority order for microcopy; tone modeled as a contextual spectrum (motivational/useful/instructive/reassuring/supportive) driven by journey stage and emotional state rather than a fixed personality; tone treated as an empirically measured usability factor (Melanie Polkosky's 862-participant factor-analysis study ranking "customer service behavior" as a top-four usability driver); an anti-idiom/global-scalability check for celebratory or lifecycle copy; and a Brand-Voice-vs-Product-Voice guardrail so restrained task-level copy isn't penalized for lacking marketing personality. `references/core.md` gains four new Content rules — `C13` (confirm-shaming anti-pattern, NN/g Deceptive Patterns), `C14` (concision-vs-precision spectrum), `C15` (non-value-assigning disability language), `C16` (singular "they" as the default third-person pronoun) — plus two applicability notes on `C01` (a domain-jargon exception for verified expert audiences, and recognition-over-recall broadened from navigation labels to every action label app-wide).
- `usability`: `references/core.md` gains a six-step confirmation-dialogue simplification technique attached to `A05R`/`A06R` (extract facts, prioritize destructive/irreversible consequences first, phrase the title as a direct question, align button labels to literally answer it, strip jargon) — a refinement technique for an existing finding, not a new competing rule ID.
- `trust`: new `O13` — when a form collects gender, sex, or other identity/demographic data, gender identity, sex assigned at birth, and pronouns are treated as distinct, optional/free-text-where-possible fields with an explicit stated purpose, narrower than `O07`'s general minimum-data-collection principle.
- `accessibility`: new `X13` (chronological-vs-spatial instructional language, WCAG SC 1.3.3 Sensory Characteristics, distinct from `X02`'s SC 1.4.1 color-alone rule) and `X14` (device-agnostic action verbs — "Select"/"Choose"/"View" over "Click"/"Tap"/"Press" — except where copy deliberately teaches a specific physical gesture).
- `review`: `references/review-model.md`'s `V04` (test realistic adverse states) gains the "stress case" framing and a discrimination-awareness example (an arbitrary age-cap validation rule excluding real centenarian users), without a new rule ID.

## 0.1.9 — form/navigation/content rule additions from an eye-tracking research comparison pass

Added a set of specific, named-source rule additions found while comparing this project's existing catalog against Jennifer Romano Bergstrom & Andrew Schall (eds.), *Eye Tracking in User Experience Design* (Morgan Kaufmann/Elsevier, 2014). Not a wholesale import of that book's full extracted item set — its eye-tracking research-methodology content (self-report bias, pupillometry/EDA/EEG, CTA-vs-RTA test protocols, data-cleaning standards) describes how to run studies, not what a static-evidence review should check, so it has no home in any existing skill; e-commerce-, social-media-, and gaming-specific verticals, and an older-adult/low-literacy population cluster, were also scoped out as a new-domain question rather than folded in by default (see the archived change's `proposal.md`/`design.md` for the full scoping rationale). Everything already covered (banner blindness/`PA09`, in-field placeholders/`F01`, inline field errors/`F07`, touch targets/`T01`-`T02`) was left untouched.

- `usability`: five new Forms & input rules (`F13`-`F17`) — primary-action-button alignment under the field column with Previous-left-of-Next ordering; top-aligned label proximity (Matteo Penzo's label-placement study); no realistic/copyable sample data in illustration graphics next to input fields; single-column layout for distinct questions (double-banking reserved for answer choices within one question); a persistent cross-step summary of previously entered data in multi-step forms. Two new Navigation rules (`N13R`-`N14R`) — standard top-right-header/footer placement for utility navigation; primacy/recency ordering for dynamic dropdown/mega-menu items. The "Search & discovery" section is renamed "Search, discovery & comparison" and gains `D06` — keep compared decision parameters (price/schedule, spec/cost) in tight horizontal proximity (the KLM flight-search redesign case). The "Always show onboarding" folk-rule guard gains a concrete citation (a mobile instruction-popup study: near-zero fixation time, 100% subsequent task failure).
- `psychology`: new `PA10` — F-pattern/top-left scanning bias in dense single-column text, and how multi-column/structured-block formatting disperses fixations; framed alongside `PA01`/`PA04` in `attention.md`.
- `product`: new `P09` — on a product-detail (single-featured-item) page, cross-sell/recommendation modules must not sit above the primary featured product; scoped by an applicability note (does not apply to browse/category/listing pages), distinct from the general `P02` hierarchy rule. New reference file `references/web.md` (the `web.md` addendum already anticipated in this project's config context) with six text-scanning/typography rules (`C07`-`C12`) for content-heavy pages: inverted-pyramid structure, front-loaded headline/subheading keywords, an ALL-CAPS reading-speed penalty, left-alignment primacy over centered/justified body text, digit-not-word numerals, and image captions as a high-fixation content element.

## 0.1.8 — five targeted rule additions from a Digital Minimalism comparison pass

Added a small number of specific, named-source rule additions found while comparing this project's existing catalog against Cal Newport's *Digital Minimalism*. Not a wholesale import of that book's ~12 extracted items (its attention-economy philosophy, digital-declutter process, solitude/default-mode-network framing, single-purpose computing, slow media, and community-organizing content stay deferred per `openspec/config.yaml`, and its core variable-reward/streak/autoplay/stopping-cue mechanisms were already covered by this project's existing `PH02`-`PH04` and four-gate ethics test) — each addition traces to a named, verifiable primary source, consistent with every other rule in this project.

- `product`: new `P08` — a feature, permission request, or onboarding flow must state a concrete user value, why it's the best available way to serve it, and explicit operating boundaries; a vague, open-ended value proposition ("stay connected," "never miss out") does not justify unconstrained access (Stanford Behavior Design Lab/Fogg Behavior Model; Apple/Android permission guidance). Distinct from the existing `P06` (identity/data gating only).
- `trust`: new `O11` — notification controls should support time-based quiet hours and sender/contact-level allowlisting, not only category toggles (Apple Focus; Android Do Not Disturb + priority senders). New `I06` — a badge/unread indicator's color/visual intensity must not signal higher urgency than the content's actual criticality (Apple HIG's badge-semantics guidance plus published color-arousal/urgency-perception research).
- `psychology`: new `PT07` — for relationship-maintenance use cases, route users toward higher-bandwidth channels (voice, video, in-person) rather than treating low-bandwidth async text/reactions as a full substitute for conversation (Sherry Turkle, MIT, *Reclaiming Conversation*). `habits.md` gained an application note: a `PH02`-`PH04` engagement-loop finding defaults to the higher end of its severity band on mobile vs. an equivalent desktop/web finding, because the device is carried on-body and continuously reachable — a calibration within the existing severity model, not a new severity level or rule ID.

## 0.1.7 — information-architecture rule and validation-technique guidance from a UX-practice book comparison pass

Added a small number of specific, named-source rule additions found while comparing this project's existing catalog against a UX-team-of-one practice book. Not a wholesale import of that book's ~25 extracted items (its own frameworks and process/evangelism content stay deferred per `openspec/config.yaml`) — each addition traces to a named, verifiable primary source, consistent with every other rule in this project.

- `product`: new `IA01`/`IA02` — information architecture (navigation/labeling/categorization) evaluated at the user/content/context intersection (Rosenfeld, Morville & Arango, *Information Architecture for the Web and Beyond*), with tree testing (Donna Spencer) recommended over visual-comp review alone to validate findability.
- `review`: new `V06` — when a finding is `NOT ASSESSABLE`/`LIKELY`, name a concrete low-cost technique to close the gap: a Five-Second Test (Christine Perfetti/User Interface Engineering) for hierarchy/first-impression claims, a Black Hat Session (Edward de Bono, "Six Thinking Hats") for structured critical review; `V02` gained a cited usability-test sample-size figure (Jakob Nielsen/NN/g's "five users" finding and its 2012 revisit).

## 0.1.6 — five targeted rule additions from an external UX-research comparison pass

Added a small number of specific, named-source rule additions found while comparing this project's existing catalog against a well-known secondary synthesis of classic UX psychology research. Not a wholesale import of that synthesis — each addition traces to a named, verifiable primary source (NN/g, an academic study, or existing platform guidance), consistent with every other rule in this project.

- `usability`: new folk-rule guard debunking "Miller's Law caps navigation at 7 visible items" (the law governs active recall, not recognition of continuously visible choices); new `R06R` distinguishing the sub-400ms flow-state finding (Doherty & Thadani, 1982) from the existing 0.1s/1s/10s perceived-response heuristic (`R01R`), so the two are no longer easy to conflate; `L07` gained a concrete "~300%" text-expansion example.
- `psychology`: new `PA09` (banner blindness) — legitimate content styled like an ad banner gets filtered out by selective attention, the mirror-image failure to `PA01`/`PA03`/`PA04`'s over-emphasis concern.
- `trust`: new `E08` — deliberate, brief friction/staging as a trust signal for high-stakes/security-sensitive actions, explicitly distinct from the existing destructive-action-confirmation rules (which prevent accidental loss, not build perceived trust), and explicitly guarded against over-applying friction to routine actions.

## 0.1.4 — remote install verified; manifest-location false start reverted

Added a `README.md` "Install" section with commands for skills.sh, the Claude Code plugin, and the Codex plugin — verified against the real public repo, not just locally.

Along the way, `.claude-plugin/`/`.codex-plugin/` were briefly moved to the repo root to make `claude plugin marketplace add owner/repo` resolve without a subdirectory. That broke something more important: Claude Code auto-discovers *any* directory literally named `skills/` next to a plugin's manifest, regardless of what `plugin.json`'s own `skills` array declares — with the manifest at the repo root, the repo's own top-level `skills/` (the skills.sh standalone distribution) got swept in too, doubling the installed skill count from 6 to 12. Reverted to the original, collision-free layout (manifests nested under `plugin/`). Remote Claude/Codex installs need a clone-then-point-at-subdirectory step instead of a bare `owner/repo` one-liner; skills.sh's remote install is unaffected and stays one line. `metadata.internal: true` was added to the plugin distribution's `SKILL.md` files as defense-in-depth against the same class of duplicate-listing issue.

Also added GitHub repo topics and five domain-specific issue labels (`review`, `usability`, `psychology`, `product`, `trust`; `accessibility` already existed as a GitHub default).

## 0.1.2 — review self-containment fix

Fixed: `review`'s generated package previously carried no rule content of its own — only lens-selection methodology — and relied on the five domain skills' packages being installed alongside it. Confirmed (research + a real isolated `npx skills add --skill ux-crux-review` install) that skills.sh has no dependency mechanism between skills, so a standalone `review` install had nothing to apply. `scripts/build.mjs` now bundles a generated copy of every domain's `references/` into review's own package under `domains/<domain>/`, in both distributions; `scripts/validate.mjs` gained a matching drift check. Also tightened a same-class cross-reference in `trust/references/core.md` that named another skill's file by path in prose.

Verified with a real isolated install: `ux-crux-review` and `ux-crux-accessibility` each install completely alone (no sibling ux-crux package present) with zero missing or escaping file references, across all twelve generated packages (six skills x two distributions).

## 0.1.0 — initial release

First build of ux-crux: six Agent Skills (`review`, `usability`, `psychology`, `accessibility`, `product`, `trust`), a shared evidence/severity/report-contract model, and a canonical-source-to-two-distributions build pipeline (standalone `ux-crux-<domain>` for skills.sh, short-named plugin skills for Claude Code and Codex).

- Migrated the full mobile UX rule catalog (191 rules across purpose/task, navigation, actions, touch/ergonomics, forms, system status, errors/recovery, onboarding/trust, search, accessibility, adaptive layout, content, interruptions, responsiveness, interaction-efficiency/focus, and psychology/ethical-persuasion) into per-domain `references/`, split into platform-agnostic core and mobile addenda.
- Added the four-gate ethical test (evidence, applicability, user benefit, agency & truthfulness) for every psychological/persuasive mechanism in the `psychology` skill.
- Added `plugin/.claude-plugin/plugin.json` + `marketplace.json` and `plugin/.codex-plugin/plugin.json`, both validated against their real manifest schemas.
- Added `skills.sh.json` marketplace grouping.
- Added 17 eval cases (11 trigger/routing cases, 6 output/report-contract cases) under `evals/`.
- Documented a fully local build/test/run workflow in `README.md` — no publishing step required to try or modify the plugin.

**Not yet included** (see `design.md`'s Non-Goals): web/desktop rule content, book-sourced rules, deterministic measurement scripts (e.g. contrast-ratio checking), and submission to any curated/official marketplace.
