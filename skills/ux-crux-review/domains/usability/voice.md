# Voice UI (VUI): command scope and persona alignment

Applies only when the reviewed evidence includes a voice user interface or voice-assistant interaction (a smart speaker skill, an in-app voice command, a voice-driven IVR-style flow). This is this project's first non-visual-modality addendum, alongside the existing `mobile.md` (touch/platform) and `web.md` (text-scanning) addenda — see `../../shared/evidence-model.md` and `severity-model.md` for how to report findings from these rules.

| ID | Rule | Evidence | Default severity | Sources |
|---|---|---|---|---|
| VU01 | A voice interaction is limited to a discrete, simple request with a concise, single-outcome result (for example a single calendar action or a single device-control command). A voice interaction that requires the user to hold, compare, or choose among a long list of spoken options is flagged, since auditory presentation is linear, ephemeral, and exceeds working-memory capacity in a way a visual list does not. Does not apply when the voice command is paired with a visual display that presents the resulting list or options — the auditory-overload concern is specific to voice-only presentation. | Strong | Major | Mark Wells, *User Experience Design* (Voice UI command scope) |
| VU02 | A VUI's sonic persona (tone, pacing, formality) is deliberately chosen to align with the product's brand and the seriousness of the interaction context; a mismatched tone — for example a flippant or sarcastic register in a serious, safety-relevant, or high-stakes context — is flagged. | Strong | Moderate | Mark Wells, *User Experience Design* (Voice UI sonic persona) |

## How the usability skill should apply these

Apply this file only when the evidence is a voice interaction; it does not apply to a screen-based interface with no voice component. Check VU01 first: does the interaction stay within a single, simple, single-outcome request, or does it ask the user to hold multiple spoken options in mind? If the evidence shows the voice command paired with a visual display (a smart display, a companion screen) that presents the resulting options, VU01's auditory-overload concern does not apply — the visual pairing resolves it. Check VU02 whenever the evidence includes the VUI's actual wording or described tone: does the sonic persona fit the brand and the stakes of the interaction, or does a flippant/sarcastic register undercut a serious context (for example a financial or safety-relevant command)? Report either rule `NOT ASSESSABLE` when the evidence does not include enough of the actual voice interaction (wording, flow) to judge it.
